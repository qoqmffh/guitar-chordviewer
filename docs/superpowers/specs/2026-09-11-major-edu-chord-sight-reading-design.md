# Major Edu > 코드초견(Chord Sight-Reading) 생성기 — 설계 스펙

- **작성일**: 2026-09-11
- **상태**: 사용자 승인 완료, 구현 대기
- **범위**: `state.activeView === 'majorEdu'`를 지금의 WIP 자리표시자에서 실제 기능으로 교체. Major Edu 메뉴의 다른 하위 기능("반주에 솔로 출제")은 이 스펙에 포함하지 않음 — 별도로 브레인스토밍 후 별도 스펙으로 다룬다.

## 배경 / 목적

실용음악과 입시 준비생이 "코드초견"(마디마다 적힌 코드 기호+리듬을 처음 보고 바로 연주하는 실기시험 형식) 연습을 반복할 수 있도록, 매번 새로운 출제지를 그 자리에서 생성해 보여준다. 서버 저장 없이 완전히 클라이언트에서만 생성/렌더링한다(요청하신 "매번 생성" 요건).

## 확정된 요구사항 (브레인스토밍에서 사용자가 직접 결정)

1. **출제지 형식**: 정식 5선보가 아니라, 마디 박스 + 코드기호 + 리듬 슬래시로 이루어진 "코드 차트" 형식(실기시험에서 실제로 쓰이는 형태). 외부 악보 렌더링 라이브러리 불필요.
2. **마디 수**: 한 장에 8마디 고정.
3. **조성**: 사용자가 12음 중 하나를 직접 고르거나(기존 스케일 페이지의 루트 선택 버튼과 같은 UI), "🎲 랜덤" 버튼으로 매번 무작위 조성도 가능.
4. **코드 난이도(2축 중 하나)** — 하/중/상 3단계:
   - **하**: 다이아토닉 트라이어드만 (I, ii, iii, IV, V, vi, vii°를 트라이어드로)
   - **중**: 다이아토닉 7th 코드 — 기존 `DIATONIC_DEGREES` 배열과 완전히 동일(I=maj7, ii=min7, iii=min7, IV=maj7, V=dom7, vi=min7, vii°=halfdim7)
   - **상**: 중 단계 + 이차도미넌트(V7/ii, V7/V, V7/vi 등) 및 보유코드(borrowed chord) 몇 개를 진행 중간에 섞음
5. **리듬 난이도(2축 중 다른 하나)** — 하/중/상 3단계, 마디 안에서 완결되는 사전 정의 리듬 패턴 중에서 무작위로 배치(자유 생성이 아니라 "패턴 뱅크에서 뽑기" 방식):
   - **하**: 마디당 1히트(온음표 하나)
   - **중**: 마디당 2히트(2분음표 두 개, 1박·3박에 하나씩)
   - **상**: 마디당 2~4히트, 당김음(싱코페이션) 패턴 몇 개를 미리 정의해두고 그 중 하나를 마디마다 무작위 배치
   - **v1 스코프 제외**: 마디를 넘어가는 타이(예: 앞마디 4박 뒤에서 당겨 다음마디 1박과 붙는 것)는 렌더링 복잡도 때문에 이번 스펙에서 제외. 모든 리듬 패턴은 한 마디 안에서 완결된다.
6. **저장/내보내기**: 화면 표시 + "PNG로 저장" 버튼까지 v1에 포함(SVG를 캔버스에 그려서 다운로드). 인쇄(Ctrl+P)는 브라우저 기본 기능으로 이미 되므로 별도 구현 안 함.
7. **영속성 없음**: Firebase나 localStorage에 생성 결과를 저장하지 않는다. 버튼 누를 때마다 그 자리에서 새로 생성하고, 새로고침하면 사라지는 게 의도된 동작.

## 데이터 모델

```js
// 한 장(8마디)의 출제지
{
  root: 7,          // 0~11, NOTES 인덱스 (조성의 으뜸음)
  chordTier: 'mid',  // 'low' | 'mid' | 'high'
  rhythmTier: 'mid', // 'low' | 'mid' | 'high'
  measures: [
    {
      hits: [
        { beat: 1, roman: 'I', chordLabel: 'Cmaj7' },
        { beat: 3, roman: 'V', chordLabel: 'G7' }
      ],
      rhythmPatternId: 'mid-2' // 어떤 리듬 템플릿을 썼는지(디버깅/재현용)
    },
    // ... 8개
  ]
}
```

- `roman`은 기존 `DIATONIC_DEGREES`의 `label`을 그대로 재사용(I, ii, iii, IV, V, vi, vii°). 상 단계에서 추가되는 이차도미넌트는 `'V7/ii'`, `'V7/V'`, `'V7/vi'` 같은 별도 표기를 쓰되, 실제 화음은 대상 다이아토닉 코드의 5도 위 도미넌트7로 계산.
- `chordLabel`은 기존 `scaleChordName(rootPC, offset, qualKey)` 패턴을 그대로 재사용해서 계산 — 새 코드 이름 생성 로직을 만들지 않는다.
- 하(트라이어드) 단계는 `QUALITIES`에 없는 "디미니쉬 트라이어드" 표기가 필요하므로, 이 기능 전용의 작은 매핑 하나만 추가한다:
  ```js
  // Major Edu 전용 — 다이아토닉 도수별 트라이어드 코드 종류(하 난이도에서만 사용).
  // QUALITIES에는 순수 디미니쉬 트라이어드가 없어서(dim7만 있음) 여기서만 별도 정의.
  var DIATONIC_TRIADS = [
    { label: 'I',    offset: 0,  qual: 'major' },
    { label: 'ii',   offset: 2,  qual: 'minor' },
    { label: 'iii',  offset: 4,  qual: 'minor' },
    { label: 'IV',   offset: 5,  qual: 'major' },
    { label: 'V',    offset: 7,  qual: 'major' },
    { label: 'vi',   offset: 9,  qual: 'minor' },
    { label: 'vii°', offset: 11, qual: 'dimTriad' } // scaleChordName엔 없는 임시 키 — 아래 참고
  ];
  ```
  `vii°` 트라이어드는 `QUALITIES`/`SCALE_CHORD_EXTRA` 어디에도 없으므로, `SCALE_CHORD_EXTRA`에 `dimTriad: { label: 'dim', intervals: [[0,'R'],[3,'b3'],[6,'b5']] }`를 하나 추가해서 `scaleChordName()`이 그대로 처리하게 한다(기존 함수 수정 없이 조회 테이블만 확장).

## 생성 알고리즘

1. **조성 결정**: `state.majorEduRoot` (버튼 선택 또는 랜덤 버튼이 0~11 중 하나를 세팅).
2. **코드 진행 생성** (8마디, 마디당 1~2개 코드 슬롯):
   - 하/중 단계: `DIATONIC_TRIADS` 또는 `DIATONIC_DEGREES`에서 마디 수만큼 도수를 뽑되, 아래 최소 규칙만 지킨다(완전한 화성학 엔진이 아니라 "그럴듯한 진행"이 목표):
     - 같은 도수가 연속 두 번 나오지 않게
     - 8마디 중 최소 한 번은 `V`(도미넌트) → `I`(토닉) 진행이 포함되게(해결감을 위해)
     - 마지막 마디는 `I`로 끝나게
   - 상 단계: 위 규칙에 더해, 8마디 중 1~2곳을 이차도미넌트(`V7/ii`, `V7/V`, `V7/vi` 중 하나, 다음 마디가 그 대상 다이아토닉 코드일 때만 배치 가능)로 대체.
3. **리듬 배치**: 마디마다 `rhythmTier`에 해당하는 패턴 뱅크에서 하나를 무작위로 골라 그 마디의 코드 슬롯 수(1개/2개/2~4개)를 결정 — 즉 코드 진행 생성 단계와 리듬 배치 단계가 서로 슬롯 개수를 맞춰가며 채워진다(리듬 패턴이 먼저 "이 마디는 히트가 몇 번"을 정하고, 거기 맞춰 코드를 그만큼 뽑는 순서가 더 단순함).

## 렌더링

기존 `buildFretboardSVG()`/`buildScaleFretboardSVG()`와 같은 방식 — 문자열 조립형 SVG, 외부 라이브러리 없음.

- 8마디를 2줄(한 줄에 4마디)로 배치, 각 마디는 세로 바 라인으로 구분된 사각 영역.
- 마디 위쪽에 코드기호 텍스트(`chordLabel`)를 히트 위치(beat)에 맞춰 가로 배치.
- 마디 아래쪽에 리듬 슬래시(사선 노트헤드 + 스템)를 히트 위치에 그리기 — 히트 개수가 적으니(마디당 최대 4개) 몇 가지 뮤직 심볼(온음표 사각형, 2분음표 스템, 슬래시 헤드)만 하드코딩한 SVG 조각으로 충분하다.
- 마지막 마디 뒤에는 종지선(굵은 마디선 두 줄) 표기.

## UI

Major Edu의 기존 WIP 자리표시자(`#app-wip`, `state.activeView === 'majorEdu'`)를 전용 뷰로 교체:

```
<div id="app-major-edu">
  <h1>Major Edu — 코드초견</h1>
  [루트음 선택 버튼 12개 + 🎲 랜덤 버튼]
  [코드 난이도 세그먼티드: 하/중/상]
  [리듬 난이도 세그먼티드: 하/중/상]
  [생성 버튼]
  [결과 SVG 악보 영역]
  [PNG로 저장 버튼] (결과가 있을 때만 노출)
</div>
```

기존 `.gt-btn`/`.gt-segmented`/`.gt-grid-fixed` 클래스를 그대로 재사용해서 스케일/코드 페이지와 톤을 맞춘다. `state.activeView`에 새 분기 추가, `WIP_VIEWS` 배열에서 `'majorEdu'` 제거.

## 테스트 방법

기존 세션에서 써온 패턴 그대로:
- Node `vm`-less 스텁으로 인라인 스크립트를 로드해서, 12개 루트 × 3개 코드난이도 × 3개 리듬난이도 = 108개 조합에 대해 생성 함수가 예외 없이 8마디를 만들어내는지 확인.
- 생성 결과 검증: 마지막 마디가 `I`로 끝나는지, 같은 도수 연속 금지 규칙이 지켜지는지, 상 단계에서 이차도미넌트가 있으면 반드시 다음 마디가 대상 코드인지.
- 브라우저 열어서 실제 SVG 렌더링 육안 확인 + PNG 저장 버튼 동작 확인.
